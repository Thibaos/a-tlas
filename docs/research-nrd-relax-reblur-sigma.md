# NRD RELAX vs REBLUR vs SIGMA (v4.17.3)

> Research date: 2026-08-26. Version verified against: **v4.17.3** — vendored copy `third_party/nrd`, header `Include/NRD.h` (`NRD_VERSION_MAJOR 4`, `NRD_VERSION_MINOR 17`, `NRD_VERSION_BUILD 3`, `NRD_VERSION_DATE "30 April 2026"`), README title "NVIDIA REAL-TIME DENOISERS (NRD) v4.17.3"; matches the latest tagged GitHub release v4.17.3. All claims below were verified against the vendored sources (`third_party/nrd/...`) cross-referenced with upstream master ([NVIDIA-RTX/NRD](https://github.com/NVIDIA-RTX/NRD)), the NVIDIA developer blog, and GitHub issues only where NRD maintainer `dzhdanNV` compares the denoisers. Primary sources only, no secondary synthesis.

## Executive answer

The three denoisers target disjoint signals and are not interchangeable: **REBLUR** and **RELAX** are alternative radiance denoisers for the same diffuse/specular GI inputs (REBLUR additionally covering ambient/specular occlusion and directional occlusion, RELAX not covering them at all), while **SIGMA** denoises only per-light shadow visibility (penumbra distance + optional translucent color) and composes with either radiance denoiser inside one instance. Mechanically, REBLUR is a recurrent multi-scale Poisson-disk blur pipeline over a temporally accumulated history driven by normalized hit distance (no second-moment tracking, hence wider usable HDR range, 63-frame cap, cheapest: 2.50 ms vs RELAX 3.20 ms for DIFFUSE_SPECULAR @1440p RTX 4080); RELAX is an SVGF-lineage A-trous filter with variance-guided edge stopping that also tracks second moments (255-frame cap, sharper/more responsive clamping, but ~28% slower, +7-10% anti-firefly overhead, and an effective FP16 `[0;250]` HDR input ceiling); SIGMA is a tiny shadow-only spatial+temporal filter (7-frame history, 0.40 ms, ~32 MB working set @1080p). There is **no clear accuracy winner**: NVIDIA's own guidance is conditional — the maintainer states RELAX handles reflections of dynamic objects better while "for static world reflection with moving camera REBLUR maybe better", and REBLUR lags more on moving-object reflections but costs less and tolerates dirtier HDR inputs. They are **not meant to run in parallel on the same signal**: RELAX and REBLUR are exclusive alternatives chosen per project/signal, whereas SIGMA is additive — `InstanceCreationDesc.denoisers` accepts any combination, "including repeating ones (for example, `RELAX_DIFFUSE`, `RELAX_DIFFUSE` and `SIGMA_SHADOW`)".

## 1. What each denoiser consumes, and its algorithm

1. **The official split.** README: "*REBLUR* - recurrent blur based denoiser; *RELAX* - A-trous based denoiser, has been designed for *[RTXDI (RTX Direct Illumination)]*; *SIGMA* - per-light shadow-only denoiser." Supported signals: *RELAX* — "Diffuse & specular radiance (+Spherical Harmonics "SH" variants, actually Spherical Gaussian "SG")"; *REBLUR* — the same radiance/SH signals **plus** "Diffuse (ambient) & specular occlusion ("OCCLUSION" variants)" and "Diffuse (ambient) directional occlusion ("DIRECTIONAL_OCCLUSION" variant)"; *SIGMA* — "Shadows from an infinite light source (sun, moon) or a local light source (omni, spot)" and "Shadows with translucency". [README](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md) (= `third_party/nrd/README.md`)
2. **The method matrix confirms the asymmetry.** `Denoiser` enum: 10 REBLUR variants (`REBLUR_DIFFUSE`, `REBLUR_DIFFUSE_OCCLUSION`, `REBLUR_DIFFUSE_SH`, `REBLUR_SPECULAR`, `REBLUR_SPECULAR_OCCLUSION`, `REBLUR_SPECULAR_SH`, `REBLUR_DIFFUSE_SPECULAR`, `REBLUR_DIFFUSE_SPECULAR_OCCLUSION`, `REBLUR_DIFFUSE_SPECULAR_SH`, `REBLUR_DIFFUSE_DIRECTIONAL_OCCLUSION`), 6 RELAX variants (`RELAX_DIFFUSE`, `RELAX_DIFFUSE_SH`, `RELAX_SPECULAR`, `RELAX_SPECULAR_SH`, `RELAX_DIFFUSE_SPECULAR`, `RELAX_DIFFUSE_SPECULAR_SH` — no occlusion variants exist), and exactly two SIGMA variants (`SIGMA_SHADOW`: `IN_PENUMBRA → OUT_SHADOW_TRANSLUCENCY`; `SIGMA_SHADOW_TRANSLUCENCY`: `IN_PENUMBRA, IN_TRANSLUCENCY → OUT_SHADOW_TRANSLUCENCY`). All share `IN_MV`, `IN_NORMAL_ROUGHNESS`, `IN_VIEWZ` guides, except REFERENCE which uses none. [Include/NRDDescs.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDDescs.h) (= `third_party/nrd/Include/NRDDescs.h`, `Denoiser` enum)
3. **REBLUR's algorithm: recurrent, geometry-driven multi-scale blur.** Its pass graph for `REBLUR_DiffuseSpecular` is Classify tiles → Hit distance reconstruction → Pre-pass → Temporal accumulation → History fix → Blur → Post-blur → Temporal stabilization → Split screen — i.e. temporal accumulation feeding progressively wider Poisson-disk blurs (config constants `REBLUR_PRE_PASS`/`REBLUR_BLUR`/`REBLUR_POST_BLUR` with radius scales 1.0→2.0 and 8-sample `g_Special8` Poisson sets), then a stabilization pass; hit distances must be pre-normalized app-side via `REBLUR_FrontEnd_GetNormHitDist`, and the denoised normalized hit distance doubles as AO/SO output. History length is packed in 6 bits: `REBLUR_MAX_ACCUM_FRAME_NUM = ((1 << 6) - 1)` = 63. [Source/Denoisers/Reblur_DiffuseSpecular.hpp](https://github.com/NVIDIA-RTX/NRD/blob/master/Source/Denoisers/Reblur_DiffuseSpecular.hpp), [Shaders/REBLUR_Config.hlsli](https://github.com/NVIDIA-RTX/NRD/blob/master/Shaders/REBLUR_Config.hlsli) (= `third_party/nrd/Shaders/REBLUR_Config.hlsli`), [Source/Reblur.cpp](https://github.com/NVIDIA-RTX/NRD/blob/master/Source/Reblur.cpp)
4. **RELAX's algorithm: variance-guided A-trous (SVGF lineage), built for RTXDI.** Its pass graph is Classify tiles → Hit distance reconstruction → Pre-pass → Temporal accumulation → History fix → History clamping → Copy → Anti-firefly → repeated A-trous iterations (`RELAX_AtrousSmem` shared-memory variant plus `AddDispatchWithArgs(RELAX_Atrous, ..., maxRepeatNum)` up to `RELAX_MAX_ATROUS_PASS_NUM`) → Split screen; the specular path carries dedicated `REFLECTION_HIT_T_PREV/CURR` textures for virtual-motion tracking, and settings expose the classic variance machinery (`RelaxAntilagSettings`, `fastHistoryClampingSigmaScale`, luminance/normal/roughness edge-stopping relaxations). Unlike REBLUR, "RELAX uses hit distances only in the Pre-Pass and for specular tracking", and it "tracks second moments of the input signal" — the direct inheritance from SVGF's variance-guided filtering. [Source/Denoisers/Relax_DiffuseSpecular.hpp](https://github.com/NVIDIA-RTX/NRD/blob/master/Source/Denoisers/Relax_DiffuseSpecular.hpp), [README](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md) (COMBINED DENOISING + OTHER sections)
5. **SIGMA's algorithm: small-radius shadow (visibility) filter, not radiance.** Inputs encode penumbra properties, not light: README's contract is "Distance to occluder (*SIGMA*)… visibility ray must be cast from the point of interest to a light source… `hit` means "occluder is hit", `miss` means "light is hit", `NoL <= 0` - 0 (it's very important!), … `NoL > 0, miss` - >= NRD_FP16_MAX". Pass graph (Sigma.cpp `Update_SigmaShadow`): Classify tiles → Smooth tiles → Copy → Blur → Post-blur → Temporal stabilization → Split screen, with a tiny temporal window (`SIGMA_MAX_HISTORY_FRAME_NUM = 7`, `SIGMA_DEFAULT_ACCUMULATION_TIME = 0.084f // sec`, `SigmaSettings { lightDirection (only for directional lights), planeDistanceSensitivity = 0.02, maxStabilizedFrameNum = 5 }`; setting `maxStabilizedFrameNum = 0` disables temporal history entirely and drops the `IN_MV` requirement per the enum comment). It outputs shadow/translucency factors — `float shadow = SIGMA_BackEnd_UnpackShadow(OUT_SHADOW_TRANSLUCENCY)` — never radiance. [Source/Sigma.cpp](https://github.com/NVIDIA-RTX/NRD/blob/master/Source/Sigma.cpp) (= `third_party/nrd/Source/Sigma.cpp`), [Shaders/SIGMA_Config.hlsli](https://github.com/NVIDIA-RTX/NRD/blob/master/Shaders/SIGMA_Config.hlsli) (= `third_party/nrd/Shaders/SIGMA_Config.hlsli`), [Include/NRDSettings.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDSettings.h) (= `third_party/nrd/Include/NRDSettings.h`, `SigmaSettings`)

## 2. Strengths, with evidence

1. **REBLUR wins on cost and HDR headroom.** README performance table (RTX 4080 @ 1440p native, defaults): "`REBLUR_DIFFUSE_SPECULAR` - 2.50 ms (3.40 ms in "SH" mode)" vs "`RELAX_DIFFUSE_SPECULAR` - 3.20 ms (4.80 ms in "SH" mode)"; anti-firefly overhead "+0-2%" for REBLUR vs "+7-10%" for RELAX; "`SIGMA_SHADOW` - 0.40 ms", "`SIGMA_SHADOW_TRANSLUCENCY` - 0.45 ms". Memory @1080p working set: `REBLUR_DIFFUSE_SPECULAR` 148.12 MB (88.88 persistent) vs `RELAX_DIFFUSE_SPECULAR` 168.94 MB (97.12); in SH mode 232.50 vs 303.94 MB; `SIGMA_SHADOW` only 31.88 MB (8.44 persistent). Because REBLUR does not track second moments, "*REBLUR* supports wider HDR ranges" while RELAX needs HDR input "in a sane range [0; 250], because the internal pipeline uses FP16 and *RELAX* tracks second moments of the input signal, i.e. `x^2` must fit into FP16 range". [README](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md) (performance + MEMORY USAGE + OTHER sections)
2. **REBLUR uniquely covers occlusion-class signals.** Only REBLUR has `*_OCCLUSION` and `*_DIRECTIONAL_OCCLUSION` methods (denoise hit-distance-only inputs `IN_DIFF_HITDIST`/`IN_SPEC_HITDIST` and direction+hitdist), with correspondingly tiny footprints (e.g. `REBLUR_DIFFUSE_OCCLUSION` 36.06 MB @1080p vs 76.19 MB for full radiance). The occlusion variants even skip anti-firefly ("not needed in occlusion mode" — `REBLUR_Config.hlsli` undefines `NRD_SUPPORTS_ANTIFIREFLY` under `NRD_MODE == OCCLUSION || DO`). [Include/NRDDescs.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDDescs.h), [Shaders/REBLUR_Config.hlsli](https://github.com/NVIDIA-RTX/NRD/blob/master/Shaders/REBLUR_Config.hlsli), [README MEMORY USAGE table](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md)
3. **RELAX's strength is responsiveness and clamping quality.** Maintainer on the same scene: "RELAX "clamping to noisy input and/or fast history" works better than in REBLUR", and its longer accumulation window (`RELAX_MAX_HISTORY_FRAME_NUM = 255`, separate `diffuseMaxAccumulatedFrameNum`/`specularMaxAccumulatedFrameNum` = 30 vs REBLUR's shared 63-bit-capped counters) plus dedicated `RelaxAntilagSettings` acceleration make it the tool when history must react aggressively to change. NVIDIA positions it explicitly for direct illumination: "*RELAX* works well with signals produced by *RTXDI* or very clean high RPP signals. The Sweet Home of *RELAX* is *RTXDI* sample." [Issue #93 comment by dzhdanNV](https://github.com/NVIDIA-RTX/NRD/issues/93#issuecomment), [Include/NRDSettings.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDSettings.h), [README](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md)
4. **SIGMA's strengths are extreme cheapness, composability, and light-count-independent scaling.** At 0.40 ms and 8.44 MB persistent @1080p it is an order of magnitude lighter than either radiance denoiser; applied "per light" with `maxStabilizedFrameNum = 0` it gives "light count independent memory usage" and "no need to manage history buffers for lights"; and it is the one denoiser that prefers blue noise ("The only exception is *SIGMA* which works better with "blue" noise"). A documented "single-pass" translucency trick even allows multi-light shadow denoising in one `SIGMA_TRANSLUCENT_SHADOW` instance. [README](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md) (MEMORY USAGE, OTHER/[SIGMA] tips, BLUE NOISE section)
5. **Shared engineering quality:** both radiance denoisers ship embedded anti-lag techniques, history-confidence inputs ("*REBLUR* and *RELAX* have embedded anti-lag techniques, but if properly computed, using confidence inputs is the best way to mitigate temporal lags"), Catmull-Rom reprojection switches, tile classification, and the shared debug/validation layer. [README INPUTS/HISTORY CONFIDENCE](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md), config headers under `third_party/nrd/Shaders/*_Config.hlsli`

## 3. Drawbacks and failure modes

1. **REBLUR: more lag on moving objects in reflections, weaker clamping.** Maintainer repro recipe for reflection ghosting ends with "move the camera and observe lags (**more lags for REBLUR, less lags for RELAX**)", and separately: "**RELAX** "clamping to noisy input and/or fast history" **works better than in REBLUR**". REBLUR's shorter 63-frame cap also bounds convergence versus RELAX's 255. [Issue #93](https://github.com/NVIDIA-RTX/NRD/issues/93), [Include/NRDSettings.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDSettings.h), [Shaders/REBLUR_Config.hlsli](https://github.com/NVIDIA-RTX/NRD/blob/master/Shaders/REBLUR_Config.hlsli)
2. **RELAX: cost, HDR-range fragility, no occlusion coverage.** ~28% slower than REBLUR non-SH (3.20 vs 2.50 ms) and ~41% slower in SH mode (4.80 vs 3.40 ms), +7-10% anti-firefly overhead, second-moment tracking caps usable HDR input near [0;250], and the method matrix simply has no RELAX equivalent for AO/SO or directional occlusion. Its tighter tuning surface is acknowledged in the confidence-input guidance: "*REBLUR/RELAX* use confidence differently, which implies custom tuning for each denoiser, but in general *RELAX* expects smaller values." [README](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md), [Include/NRDDescs.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDDescs.h)
3. **Both radiance denoisers share structural limits.** Specular tracking excludes self-motion of reflected objects ("Yes, it's a limitation" — the root cause of the reflection-ghosting class of issues; long-term fix "user-provided MVs for objects in reflection" is still R&D), and `cameraAttachedReflectionMaterialID` needed a v4.11.1-era regression fix in TemporalStabilization confirmed by the maintainer in August 2026 ("my earlier comments were misleading… You were right: `smbPixelUv` must also be used in "TemporalStabilization""). [Issue #93](https://github.com/NVIDIA-RTX/NRD/issues/93), [Issue #106](https://github.com/NVIDIA-RTX/NRD/issues/106)
4. **SIGMA: scope-limited and fiddly for many lights.** It denoises visibility only — it cannot consume or produce radiance by construction (inputs are penumbra/translucency encodings, output is `OUT_SHADOW_TRANSLUCENCY`). The multi-light single-pass variant is explicitly caveated: "**This solution is limited** and hard to use… if shadows overlap, a separate pass is needed to analyze noisy input and classify pixels as *umbra* - *penumbra*… it is not recommended to mix 1 cd and 100000 cd lights, since FP32 texture will be needed for a weighted sum." It requires `lightDirection` setup for sun shadows and blue-noise scheduling to avoid shimmering. [Include/NRDDescs.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDDescs.h), [README [SIGMA] tips](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md)
5. **API churn affects all three** and matters for a vendored copy: `UPDATE.md` records per-denoiser breaking changes across every minor version (settings renames/collapses in v3.0, SIGMA `IN_SHADOWDATA → IN_PENUMBRA` in v4.8, REBLUR `maxBlurRadius` rescale ×2 in v4.9, antilag rework in v4.11, material-test → `minMaterialForDiffuse/Specular` in v4.14), so pinning the exact tag is mandatory before writing bindings. [= `third_party/nrd/UPDATE.md`](https://github.com/NVIDIA-RTX/NRD/blob/master/UPDATE.md)

## 4. Accuracy verdict: is there a winner?

1. **NVIDIA's own guidance is conditional, not absolute.** The maintainer's recap in the canonical ghosting thread: "SHORT TERM: - use RELAX (better for reflections of dynamic objects, for static world reflection with moving camera REBLUR maybe better)". In the opening reply he also noted REBLUR "offers a bit more" in its validation/debug surface ("I would prefer to see REBLUR validation as well because it offers a bit more"), and elsewhere documents RELAX's superior clamping. Read together: **RELAX is more accurate precisely where history must respond fast** (dynamic content visible in glossy reflections, RTXDI-style direct lighting, aggressive clamping to noisy/fast history); **REBLUR is the equal-or-better choice for slowly-varying low-spp radiance fields** (static-world GI under camera motion) at 22% lower cost, wider HDR tolerance, and richer occlusion modes. [Issue #93 comments by dzhdanNV](https://github.com/NVIDIA-RTX/NRD/issues/93)
2. **No published benchmark crowns either denoiser.** The README ships only cost/memory tables, never IQ rankings between REBLUR and RELAX; the NVIDIA launch blog predates RELAX entirely and speaks of NRD as a whole ("designed to work with low rpp (ray per pixel) signals, and is the only denoiser variable that works with 0.5 or 1 ray per pixel", "NRD offers better image quality than SVGF"). Any claim that one is globally "most accurate" would be fabrication; the honest answer is **condition-dependent**, with the maintainer's issue #93 sentence as the only direct NVIDIA-authored comparison found. [NVIDIA developer blog, Oct 2020](https://developer.nvidia.com/blog/nvidia-real-time-denoiser-delivers-best-in-class-denoising-in-watch-dogs-legion/), [README](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md)
3. **For atlas-rt specifically** (inference, not an NVIDIA statement): the existing decision to use `REBLUR_DIFFUSE_SPECULAR` for 1-spp diffuse+specular GI remains consistent with the evidence above — static voxel world, no RTXDI, HDR range and perf favor REBLUR; RELAX would become attractive only if dynamic-object reflections dominate the failure budget. SIGMA is orthogonal and only enters if per-light shadow visibility is ever split out of the path-traced integral.

## 5. Parallel use semantics

1. **One instance, arbitrary denoiser mix.** `InstanceCreationDesc { AllocationCallbacks allocationCallbacks; const DenoiserDesc* denoisers; uint32_t denoisersNum; }` with `DenoiserDesc { Identifier identifier; Denoiser denoiser; }` — the caller lists any set of methods, each with its own identifier so `GetComputeDispatches(identifiers, ...)` can collect dispatches per denoiser and `SetDenoiserSettings(identifier, ...)` addresses each individually. UPDATE.md (v4.2) states the semantics verbatim: "A single NRD instance can now include any combination of denoisers, including repeating ones (for example, `RELAX_DIFFUSE`, `RELAX_DIFFUSE` and `SIGMA_SHADOW`)." [Include/NRDDescs.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDDescs.h) (= `third_party/nrd/Include/NRDDescs.h`, `InstanceCreationDesc`), [= `third_party/nrd/UPDATE.md` "To v4.2"](https://github.com/NVIDIA-RTX/NRD/blob/master/UPDATE.md)
2. **RELAX and REBLUR are exclusive alternatives for the same signal.** Both families bind identical resource slots for identical signals (`REBLUR_DIFFUSE_SPECULAR` and `RELAX_DIFFUSE_SPECULAR` both consume `IN_DIFF_RADIANCE_HITDIST` + `IN_SPEC_RADIANCE_HITDIST` and produce the matching outputs), so running both on the same signal would duplicate cost with no defined consumer — the intended pattern is choosing one per signal. Nothing in the library forbids including both in one instance (each gets independent pipelines, permanent-pool history, and settings via its own `Add_ReblurDiffuseSpecular` / `Add_RelaxDiffuseSpecular` branch in `InstanceImpl::AddDenoiser`), which is precisely what makes mixed setups like `REBLUR_DIFFUSE` for GI + `RELAX_SPECULAR` for reflections expressible. [Include/NRDDescs.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDDescs.h), [Source/InstanceImpl.cpp](https://github.com/NVIDIA-RTX/NRD/blob/master/Source/InstanceImpl.cpp) (= `third_party/nrd/Source/InstanceImpl.cpp`, `AddDenoiser` dispatch chain)
3. **SIGMA composes freely with either.** SIGMA reads none of the radiance slots — its noisy inputs are `IN_PENUMBRA` (packed via `SIGMA_FrontEnd_PackPenumbra`, two variants for infinite/local lights) and optionally `IN_TRANSLUCENCY`, its output `OUT_SHADOW_TRANSLUCENCY` unpacks to a scalar shadow or `float3` translucent color — so it shares only the common guides (`IN_VIEWZ`, `IN_NORMAL_ROUGHNESS`, and `IN_MV` unless `stabilizationStrength = 0`) with a radiance denoiser and adds its own small pipeline (`ClassifyTiles…TemporalStabilization`, 7 shaders embedded in `Sigma.cpp`) to the shared instance. Repeating `SIGMA_SHADOW` entries under different identifiers is the sanctioned way to scale across lights. [Include/NRDDescs.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDDescs.h), [Include/NRDSettings.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDSettings.h), [Source/Sigma.cpp](https://github.com/NVIDIA-RTX/NRD/blob/master/Source/Sigma.cpp)
4. **Sample behavior.** The reference integrations treat REBLUR/RELAX as a runtime choice, not a stack: switching the active denoiser in the NRD-Sample triggers a history reset (`accumulationMode = CLEAR_AND_RESTART`), and the sample's tracing shader branches `if (RELAX) { RELAX_FrontEnd_PackRadianceAndHitDist(...) } else { REBLUR_FrontEnd_PackRadianceAndNormHitDist(...) }` — one packing path, one radiance denoiser at a time, with SIGMA available alongside for shadows. *(Inference from README integration pseudo-code and the previously documented sample reset flow; the sample repo itself was not re-read this session.)* [README integration example](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md), [docs/research-nrd-reblur-path-tracing.md §5](research-nrd-reblur-path-tracing.md)
