# NRD ReBLUR for 1-spp path tracing (v4.17.4, ticket 01)

> Research ticket: [.scratch/path-tracing/issues/01-nrd-reblur-research.md](../.scratch/path-tracing/issues/01-nrd-reblur-research.md)
> Verification date: NRD master at v4.17.4 (`NRD_VERSION_DATE` "2 May 2026", header `Include/NRD.h`); latest tagged GitHub release v4.17.3 (2026-04-30); all claims verified against the NVIDIA-RTX/NRD repo (master), the nvpro-samples/vk_denoise_nrd Vulkan sample, the NVIDIA-RTX/NRD-Sample reference path tracer, and crates.io, primary sources only, no secondary commentary.

## Executive answer

NRD is the right tool and the FFI lift is feasible: it is a **C-API, vendor-agnostic compute library** (D3D11/12 + Vulkan, HLSL compiled to SPIR-V) that **makes no GPU calls itself**. The app builds pipelines from precompiled SPIR-V blobs and executes the per-frame compute-dispatch list it returns. It is actively maintained (v4.17.x line, releases every few weeks; v4.17.3 fixed ReBLUR artifacts on AMD configs, v4.17.4 header dated 2 May 2026) and its README names "**1 path/pixel path tracing**" as the primary use case. The correct denoiser for atlas-rt's diffuse + PBR-specular GI at 1 spp is **REBLUR_DIFFUSE_SPECULAR** (2.55 ms @ 1440p on RTX 4080, native; ReLAX is the RTXDI-oriented A-trous alternative, SIGMA is shadows-only). Two findings change the ticket's assumptions: (1) the license is **not BSD-3**. It is the proprietary "NVIDIA RTX SDKs LICENSE" EULA (GitHub API: `NOASSERTION`), which matters for a MIT-licensed repo; (2) the only existing crate, **nrd-sys (0.2.0, Dec 2023), is stale and wraps a forked NRD with a diverged API**. The bindings should be generated fresh against upstream v4.17.x (surface is small: 9 `extern "C"` functions + POD structs). The real work is the Vulkan glue (mirror of vk_denoise_nrd's ~450-line `NRDWrapper`), not the FFI. ReBLUR's input contract is exact and well-documented: de-modulated diffuse+specular radiance with in-lobe 1st-bounce hit distance, normal/roughness, linear viewZ, and **backward-pointing screen-space motion vectors in pixels per frame** (2.5D `.z = viewZprev - viewZ` recommended), with temporal resets done per-frame via `AccumulationMode::RESTART/CLEAR_AND_RESTART`. Known 1-spp failure modes (ghosting of moving objects in reflections, camera-attached ghosting, fireflies beyond ~20-30x energy, convergence within the ~30-frame accumulation window) are documented in issues and README guidance and are testable with the effort's stochastic-validation harness.

SteamDeck, plus a RELAX/SH perf improvement. Release cadence is rapid and current (v4.17.0 → v4.17.3 with visible release notes; v4.16.0 → v4.17.0 in the same line), and the repo (NVIDIA-RTX/NRD, ~825 stars, language HLSL, created 2020, moved from NVIDIAGameWorks/RayTracingDenoiser) is not archived. [LICENSE.txt](https://github.com/NVIDIA-RTX/NRD/blob/master/LICENSE.txt), [repo API license field](https://api.github.com/repos/NVIDIA-RTX/NRD), [issues](https://github.com/NVIDIA-RTX/NRD/issues)
3. **What's in it.** NRD = REBLUR (recurrent-blur denoiser), RELAX (A-trous denoiser "designed for RTXDI"), SIGMA (per-light shadow-only denoiser), and a REFERENCE denoiser (pure temporal accumulation, no spatial filtering, used to estimate achievable temporal signal quality). Supported signals: REBLUR and RELAX both handle diffuse & specular radiance, with SH (spherical-Gaussian) variants, occlusion variants, and diffuse directional occlusion; SIGMA handles infinite/local light shadows (incl. translucency). NVIDIA's own description: "ReBLUR: Blur the information over multiple frames; good for low samples per pixel." atlas-rt's use case (diffuse + PBR specular GI at 1 spp) is exactly `REBLUR_DIFFUSE_SPECULAR`. [README](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md), [NVIDIA developer blog](https://developer.nvidia.com/blog/nvidia-real-time-denoiser-delivers-best-in-class-denoising-in-watch-dogs-legion/), [GTC 2020 ReBLUR deck](https://developer.download.nvidia.com/video/gputechconf/gtc/2020/presentations/s22699-fast-denoising-with-self-stabilizing-recurrent-blurs.pdf)

## 2. ReBLUR input contract (per-pixel)

1. **Guide (non-noisy) inputs must not contain NAN/INF.** `IN_MV` (motion, RG16f+ for 2D screen-space, RGBA16f+ for 3D world-space), `IN_NORMAL_ROUGHNESS` (RGBA8+; world-space normal + *linear* roughness = `sqrt(m)` where `m = alpha` GGX; diffuse pixels should pass `1.0` as roughness; encoding fixed at SDK build time via `NRD_NORMAL_ENCODING`/`NRD_ROUGHNESS_ENCODING` and queryable from `LibraryDesc`), `IN_VIEWZ` (R16f+, linear view-space Z of the primary ray), optional `IN_DIFF/SPEC_CONFIDENCE` (R8+, history confidence 0-1; may be at lower resolution, linearly upscaled) and `IN_DISOCCLUSION_THRESHOLD_MIX` (R8+). NRD "doesn't use baseColor and metalness anywhere". Materials must be de-modulated on the app side (`NRD_MaterialFactors`; diffuse: `NRD(diffuseRadiance / albedo) * albedo`; specular: `NRD(specularRadiance * BRDF / envBRDF) * envBRDF`). [README #inputs](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md), [NRDDescs.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDDescs.h), [Shaders/NRD.hlsli](https://github.com/NVIDIA-RTX/NRD/blob/master/Shaders/NRD.hlsli)
2. **Noisy inputs: radiance + normalized hit distance.** `IN_DIFF_RADIANCE_HITDIST` / `IN_SPEC_RADIANCE_HITDIST` (RGBA16f+; `.a` = normalized hit distance, packed with `REBLUR_FrontEnd_PackRadianceAndNormHitDist`), or hit distance as a separate R8+ input. Radiance rules: no material information (de-modulated), **not premultiplied by exposure**, diffuse and specular **separated at the primary hit**, sampled in-lobe (cos-weighted for diffuse, VNDF for specular). NAN/INF allowed only outside the viewport (`rectSize`) or outside the denoising range (`abs(viewZ) >= denoisingRange`). [Shaders/NRD.hlsli](https://github.com/NVIDIA-RTX/NRD/blob/master/Shaders/NRD.hlsli), [README #inputs](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md)
3. **Hit-distance semantics, exactly what the DDA provides.** NRD expects **in-lobe `hitT`**: for a 1-bounce path tracer the README's baseline is `hitDistance = length(B - A)`, the first-bounce ray segment, which is precisely the distance atlas-rt's DDA traversal returns. It is normalized by the app before packing: `normHitDist = saturate(hitDist / f)` with `f = (A + viewZ * B) * lerp(C, 1.0, smc)` (`smc` = roughness-based lobe-spread curve), defaults `ReblurHitDistanceParameters { A=3, B=0.1, C=20 }`. The diffuse path passes roughness `1.0` into this normalization. ReBLUR uses hit distance for tracking (specular virtual motion), disocclusion, and occlusion output. It must be meaningful, not a debug value. [Shaders/NRD.hlsli](https://github.com/NVIDIA-RTX/NRD/blob/master/Shaders/NRD.hlsli), [NRDSettings.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDSettings.h), [README example shader](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md)
4. **CommonSettings: matrices and per-frame state.** Column-major, **non-jittered** `viewToClipMatrix`, `viewToClipMatrixPrev`, `worldToViewMatrix`, `worldToViewMatrixPrev` (camera delta must be included in prev if the coordinate system moves with the camera; optional `worldPrevToWorldMatrix` for portal-style teleports without history reset, off by default), `motionVectorScale[3]`, `cameraJitter[2]`/`cameraJitterPrev[2]` (in `[-0.5; 0.5]` UV), `resourceSize[2]`/`resourceSizePrev[2]`/`rectSize[2]`/`rectSizePrev[2]` (dynamic-resolution scaling), `viewZScale`, `timeDeltaBetweenFrames`, `denoisingRange` (default 500000 units; pixels with `viewZ < denoisingRange` are valid. Set sky/INF pixels beyond it), `disocclusionThreshold` (0.01) + `disocclusionThresholdAlternate` (0.05), `strandThickness`, `splitScreen`, `frameIndex` (must increment by 1 per rendered frame), `accumulationMode`, `isMotionVectorInWorldSpace`, `enableValidation`. [NRDSettings.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDSettings.h)
5. **Full-res vs half-res.** NRD is inherently **full-res**: "all inputs must have the same resolution — logical FULL resolution". The only half-resolution paths are (a) `CheckerboardMode` (noisy inputs tightly packed into the **left half** of the texture, input pixel = 2x1 screen pixels, upsampling handled internally. OFF is explicitly recommended) and (b) DRS via `resourceSize`/`rectSize`. There is no resize API. A resolution change means destroying and recreating the instance. The NRD-Sample's three tracing variants are: full-res probabilistic lobe selection (recommended main use case), half-res checkerboard (0.5 diffuse + 0.5 specular rays), full-res 1+1 rays. For atlas-rt at 1 spp the recommended configuration is **full-res probabilistic lobe selection with `HitDistanceReconstructionMode::AREA_3X3`** (hit-distance reconstruction from 3x3 neighbors; requires lobe-selection probability clamped to `[1/4; 3/4]` and Bayer dithering instead of white noise). [NRDSettings.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDSettings.h), [README](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md), [NRD-Sample](https://github.com/NVIDIA-RTX/NRD-Sample)
6. **ReblurSettings (per-denoiser, set at least once).** Key defaults: `maxAccumulatedFrameNum = 30` (hard cap `REBLUR_MAX_HISTORY_FRAME_NUM = 63`; "always accumulate in seconds not frames", `GetMaxAccumulatedFrameNum(accumulationTime = 0.5 s, fps)`, defaults tuned for 60 FPS), `maxFastAccumulatedFrameNum = 6`, `maxStabilizedFrameNum = 63` (0 disables the stabilization pass), `historyFixFrameNum = 3` (reconstructed frames after a history reset), `diffusePrepassBlurRadius = 30`, `specularPrepassBlurRadius = 50`, `minBlurRadius = 1`, `maxBlurRadius = 30`, `lobeAngleFraction = 0.15`, `roughnessFraction = 0.15`, `planeDistanceSensitivity = 0.02`, `fireflySuppressorMinRelativeScale = 2.0`, `enableAntiFirefly = true` (default since v4.17, +0-2% cost), `checkerboardMode = OFF`, `hitDistanceReconstructionMode = OFF`, `returnHistoryLengthInsteadOfOcclusion = false`, plus `ReblurHitDistanceParameters`, `ReblurAntilagSettings`, `ReblurResponsiveAccumulationSettings`, `ReblurConvergenceSettings` (v4.17+). [NRDSettings.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDSettings.h)

## 3. API surface & Vulkan integration model

1. **The C API is tiny and dispatch-oriented.** `CreateInstance(InstanceCreationDesc, Instance*&)`, `DestroyInstance`, `GetLibraryDesc`, `GetInstanceDesc`, `SetCommonSettings` (once per frame), `SetDenoiserSettings` (per denoiser, not necessarily every frame), `GetComputeDispatches(identifiers, → DispatchDesc* & n)` (returned memory owned by the instance, overwritten by the next call), plus two string helpers. All `extern "C"` (`__stdcall` on Win32). `DispatchDesc` = per-dispatch constant-buffer data + resource bindings (SRV/UAV, resource type, pool index) + `gridWidth/gridHeight`. **NRD makes no GAPI calls**. The app executes the dispatches as compute shader invocations. [Include/NRD.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRD.h), [NRDDescs.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDDescs.h)
2. **Resource model.** The instance describes a **permanent pool** (history textures the app must not touch between frames) and a **transient pool** (aliasable by the app after denoising), plus per-pipeline resource ranges and a `DescriptorPoolDesc` (per-set max textures/storage textures, totals, `setsMaxNum`) that documents the non-push-descriptor binding path. Formats come from an NRD `Format` enum mapped to Vulkan formats (incl. `A2R10G10B10_UINT_PACK32`, `B10G11R11_UFLOAT_PACK32`, `E5B9G9R9_UFLOAT_PACK32`). No resize: recreate the instance on resolution change. [NRDDescs.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDDescs.h), [README API terminology](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md)
3. **Vulkan binding model (verified against vk_denoise_nrd's NRDWrapper).** Two descriptor sets per pipeline layout: **set 0 = per-pipeline texture bindings** (SAMPLED_IMAGE / STORAGE_IMAGE), **set 1 = samplers + constant buffer** (2 samplers, NEAREST_CLAMP and LINEAR_CLAMP, clamp-to-edge, effectively immutable; 1 UBO of `constantBufferMaxDataSize`). The wrapper hard-asserts `constantBufferAndSamplersSpaceIndex == 1 && resourcesSpaceIndex == 0`, with the comment "a hardcoded assumption that NRD promised not to break". Pipeline layouts are built from `LibraryDesc::spirvBindingOffsets` (constantBufferOffset, samplerOffset, textureOffset, storageTextureOffset). Per dispatch: transition bound textures to SHADER_READ/SHADER_WRITE (**everything runs in `VK_IMAGE_LAYOUT_GENERAL`**), `vkCmdPipelineBarrier` between passes, constant buffer updated via `vkCmdUpdateBuffer` + barriers (push constants supported for the no-UBO case), bind the global set, `vkCmdPushDescriptorSetKHR` for textures, `vkCmdDispatch(gridWidth, gridHeight, 1)`. ReBLUR's pass list (Source/Reblur.cpp) is CLASSIFY_TILES → HITDIST_RECONSTRUCTION → PREPASS → TEMPORAL_ACCUMULATION → HISTORY_FIX → BLUR → POST_BLUR → TEMPORAL_STABILIZATION, each in multiple compiled permutations. [nrd_wrapper.cpp](https://github.com/nvpro-samples/vk_denoise_nrd/blob/master/RealtimeDenoiser/src/nrd_wrapper.cpp), [Source/Reblur.cpp](https://github.com/NVIDIA-RTX/NRD/blob/master/Source/Reblur.cpp)
4. **Vulkan requirements are minimal: no RT, no vendor extensions.** Storage images, sampled images, a UBO, 2 samplers, optional `VK_KHR_push_descriptor` (the sample uses it; `DescriptorPoolDesc` exists precisely for the regular-set path) and optional immutable samplers. NRD shaders are HLSL compiled to **precompiled SPIR-V** by dxc at SDK build time (`NRD_EMBEDS_SPIRV_SHADERS` ON by default) and handed to the app as bytecode blobs; `NRD_GLSL 1` makes `NRD.hlsli` emit GLSL-compatible syntax for the app-side front-end functions. This is plain compute on any queue, trivially satisfiable by atlas-rt's existing Vulkan device, and the dispatches slot into the taskgraph model as a single node (raw barriers + dispatch recording; the wrapper's per-pass barrier approach maps 1:1 to a taskgraph node that records into the flight's command buffer via raw handles). [vk_denoise_nrd README](https://github.com/nvpro-samples/vk_denoise_nrd), [nrd_wrapper.cpp](https://github.com/nvpro-samples/vk_denoise_nrd/blob/master/RealtimeDenoiser/src/nrd_wrapper.cpp), [README build options](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md)
5. **Cross-vendor: yes.** NRD is API-agnostic (D3D11/12 + Vulkan); v4.17.3's headline fix was a ReBLUR visual-artifact bug on **AMD configs including SteamDeck**; `NRD.h` credits "invaluable testing on AMD/Linux"; ReBLUR ships in Unity HDRP (used across AMD/Intel/NVIDIA hardware); and the license's NVIDIA-GPU-only clause applies to DLSS/NGX, not NRD. No Intel-specific evidence found, but nothing in the codebase (pure SPIR-V compute) is vendor-restricted. The integration layer alternative (NRI-based `NRDIntegration`) is for engines that can expose native GAPI pointers, not the Rust path. The "native implementation" variant is the one for atlas-rt. [Releases](https://github.com/NVIDIA-RTX/NRD/releases), [Include/NRD.h credits](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRD.h), [README](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md)

## 4. Rust FFI

1. **The only existing crate is stale and fork-based.** `nrd-sys` (crates.io, v0.2.0 published 2023-12-17, MIT OR Apache-2.0, ~2.9k total downloads, 14 recent) targets Vulkan and auto-downloads precompiled binaries built from a **custom NRD fork** (dust-engine/NVIDIA_RayTracingDenoiser) that changed the allocator interface (passes size/alignment on `free`, required by Rust's allocator API) and diverged the instance-creation API (`render_width`/`render_height` inside `DenoiserDesc`, not in upstream). It predates the v4.16/v4.17 API rework (ReblurSettings reshape, `IN_BASECOLOR_METALNESS` removal, settings renames). Verdict: usable as a reference for binding shape, **not** as a dependency. It would pin the project to a 2023 fork of a fast-moving SDK. [crates.io API](https://crates.io/api/v1/crates/nrd-sys), [dust-engine/nrd-sys](https://github.com/dust-engine/nrd-sys)
2. **Fresh bindings are cheap.** The public surface is 9 `extern "C"` functions + POD structs (`CommonSettings`, `ReblurSettings`, `InstanceCreationDesc`, `DispatchDesc`, ...). The headers are C++ with default member initializers, so the pragmatic path (mirroring nrd-sys) is hand-written `#[repr(C)]` structs + `Default` impls with the documented defaults, a few hundred lines, fully reviewable, or bindgen with a small C shim if struct drift is a concern. A C++ runtime is unavoidable for the NRD lib itself (it's C++); nrd-sys's precompiled binaries show the static-lib + system-runtime approach works on Windows and Linux. The SDK build is CMake (`NRD_EMBEDS_SPIRV_SHADERS=ON` default; needs dxc on PATH for shader compilation; `NRD_NORMAL_ENCODING`/`NRD_ROUGHNESS_ENCODING` fixed at deploy time; `NRD_NRI` OFF for the native path). From Rust: `build.rs` + the `cmake` crate, static link. [Include/NRD.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRD.h), [README build section](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md), [dust-engine/nrd-sys](https://github.com/dust-engine/nrd-sys)
3. **The real effort is the Vulkan glue and the front-end shader port, not the FFI.** The reference implementation of the native-Vulkan path is vk_denoise_nrd's `NRDWrapper` (~450 lines C++: texture pools, samplers, UBO, pipeline layouts from `spirvBindingOffsets`, compute pipelines from SPIR-V blobs, per-dispatch barriers + constants + push descriptors). Porting that to Rust + vulkano is on the order of 800-1200 LOC (vulkano has no push-descriptor API. Use the `DescriptorPoolDesc` regular-set path or raw handles; `ShaderModule::from_bytes` for the precompiled blobs). The app-side shader contract (packing radiance+hitdist, normal/roughness, `REBLUR_FrontEnd_GetNormHitDist`, `NRD_MaterialFactors`, unpack on output) is a GLSL port of `NRD.hlsli` (~300-500 LOC) or compiling `NRD.hlsli` directly with `NRD_GLSL 1`. **Rough total: 1.5-3k LOC of new Rust+GLSL for a production denoiser.**
4. **Versus the in-house SVGF fallback.** An SVGF-style denoiser (temporal accumulation, variance estimation, edge-stopping A-trous, anti-lag/history reconstruction, plus specular handling approaching ReBLUR's virtual-motion tracking) is 1-2k LOC of shaders *plus* months of tuning to approach NRD's quality (ReBLUR is 8 tuned passes; the README documents its anti-lag, history-fix, convergence and firefly machinery). NRD's costs are: proprietary license, black box (closed shaders), HLSL→SPIR-V toolchain, and per-frame dispatch-driver code. The decision framing for ticket 08: **the FFI lift is bounded and well-trodden; the deciding factors are licensing and black-box testability, not engineering risk.** [nrd_wrapper.cpp](https://github.com/nvpro-samples/vk_denoise_nrd/blob/master/RealtimeDenoiser/src/nrd_wrapper.cpp), [Source/Reblur.cpp](https://github.com/NVIDIA-RTX/NRD/blob/master/Source/Reblur.cpp), [README](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md)

## 5. Motion vectors and temporal resets

1. **Convention: backward-pointing screen-space, pixels per frame.** NRD expects `pixelUvPrev = pixelUv + mv.xy` (UV in [0,1]), the "old = new + MV" rule. The NRD-Sample's `GetMotion` computes `motion.xy = (sampleUvPrev - sampleUv) * gRectSize`, i.e. **pixels per frame** ("scaling to 'pixel' unit significantly improves utilization of FP16"), with `motion.z = viewZprev - viewZ` (2.5D, recommended over 3D due to FP16 imprecision), and the sample sets `motionVectorScale = {1/rectW, 1/rectH, 1}` with `isMotionVectorInWorldSpace = false`. README rules: `motionVectorScale[2] == 0` for 2D, `!= 0` for 2.5D; 3D world-space mode requires **camera motion excluded** (all-zero MVs for a static scene even when the camera moves. It's in the matrices). [NRD-Sample Shared.hlsli](https://github.com/NVIDIA-RTX/NRD-Sample/blob/9deb12a5408c4e2e07a6ff261f0a1051dd22f5d6/Shaders/Include/Shared.hlsli), [NRDSample.cpp](https://github.com/NVIDIA-RTX/NRD-Sample/blob/f5a574e6eb630f48b89437a224dede75beed4dcb/Source/NRDSample.cpp), [README #inputs](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md)
2. **Camera-only motion for a static voxel world.** Exactly the sample's path: transform the current-frame surface position `X` by the **previous** frame's matrices (`worldToViewMatrixPrev` → `viewToClipMatrixPrev`), reproject, and take the UV delta. `worldToViewMatrixPrev` carries the camera delta. atlas-rt needs prev-view-proj (already a normal renderer requirement) and per-pixel `X` at the primary hit (available from the DDA + viewZ). Disocclusion handling is NRD's `disocclusionThreshold` (default 0.01, slope-scaled) + history rejection.
3. **Temporal reset semantics.** There is no camera-cut flag. Reset is `CommonSettings::accumulationMode = RESTART` **for a single frame** ("It's recommended to set ... to RESTART for a single frame, if a history reset is needed"; `CLEAR_AND_RESTART` if history buffers are recreated or contain garbage), and `frameIndex` must restart its sequence after a non-CONTINUE. After a reset, `historyFixFrameNum` (default 3) frames of 5x5 history reconstruction smooth the re-accumulation. The NRD-Sample triggers `CLEAR_AND_RESTART` on first frame, denoiser switch, ortho switch and its "Reset" button; `InstanceImpl::SetCommonSettings` forces `CLEAR_AND_RESTART` on first use and drops splitScreen state on any reset. Portal-style teleports that must *not* reset use `worldPrevToWorldMatrix` (opt-in via `NRD_USE_PREV_WORLD_SPACE_MATRIX`, off by default). For atlas-rt: camera cuts/teleports → one frame of `RESTART`; scene edits that invalidate history buffers → `CLEAR_AND_RESTART`. [NRDSettings.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDSettings.h), [README guidance](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md), [NRDSample.cpp](https://github.com/NVIDIA-RTX/NRD-Sample/blob/f5a574e6eb630f48b89437a224dede75beed4dcb/Source/NRDSample.cpp), [Source/InstanceImpl.cpp](https://github.com/NVIDIA-RTX/NRD/blob/master/Source/InstanceImpl.cpp)

## 6. Failure modes for 1-spp path tracing (black-box validation)

1. **Ghosting / lag of moving objects in reflections** is the recurring complaint: issue #93 (maintainer repro recipe: roughness override 0.05-0.08, metalness 1, no normal map, moving camera, "more lags for REBLUR, less for RELAX"), issue #110 (racing-game reflections), issue #106 (**camera-attached objects**, where `CommonSettings::cameraAttachedReflectionMaterialID` helps but "is only an improvement for critical cases, not a generic solution. A generic solution requires reflection MVs, which NRD currently doesn't ask for"). [issue #93](https://github.com/NVIDIA-RTX/NRD/issues/93), [issue #106](https://github.com/NVIDIA-RTX/NRD/issues/106), [issue #110](https://github.com/NVIDIA-RTX/NRD/issues/110), [NRDSettings.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDSettings.h)
2. **Darkening/brightening at history discards.** v4.17.1 fixed "potentially brighter outlines on geometry 'in-shadows' edges, where history is discarded"; ReBLUR's own source warns that the hit-distance weight + feedback loop can produce color banding ("crunched colors") when accumulation-speed limits are hit; v4.15.0 fixed "rare light leaking caused by a greedy disocclusion threshold relaxation". Contact-shadow detail depends on hit-distance weight tuning (v4.17.1: "tuned 'hitT' weight to better preserve contact details... fixed an ancient related regression ruining specular contact shadows"). [Releases](https://github.com/NVIDIA-RTX/NRD/releases), [REBLUR_Common.hlsli](https://github.com/NVIDIA-RTX/NRD/blob/master/Shaders/Include/REBLUR_Common.hlsli)
3. **Fireflies.** README: "high-energy fireflies in the input signal should be avoided". Energy increase beyond ~20-30x (≈ 0.05 minimum probability) is hard to remove within the accumulation window; `enableAntiFirefly` (default on since v4.17, +0-2%) plus `fireflySuppressorMinRelativeScale` help but the input must not be pathological. [README #inputs](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md)
4. **Convergence within the window is an input requirement.** "the input signal must converge *reasonably well*" for the accumulated frame count (default 30; cap 63); the `REFERENCE` denoiser exists specifically to estimate temporal signal quality. Blue-noise guidance (v4.17.3 README section): NRD's baseline is white noise; blue noise stabilizes 0.5-1 rpp output (Heitz Owen-scrambled Sobol recommended over STBN), and probabilistic lobe selection must add a global temporal jitter to the Bayer RNG or it "pokes holes" with directional bias. [README #inputs and #blue-noise](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md)
5. **Validation tooling ships with NRD**, exactly what the effort's stochastic-validation culture needs: `enableValidation` → `OUT_VALIDATION` overlay, `splitScreen` (noisy vs denoised), the README's antilag guidance ("use the validation layer output to ensure diff/spec frames visualization stays in the 'violet' zone"), and the triage workflow ("reproduce in the NRD sample → add a test → attach a `.bin`"). The black-box implication: NRD internals are closed and can't be unit-tested, so atlas-rt's harness should validate **end-to-end** (per-frame mean/variance, ghosting detectors on camera pans, firefly counts, reset-correctness on teleports) and **pin the NRD version** (SDK + embedded SPIR-V are build inputs); cross-vendor regressions are real (the v4.17.3 AMD bug) so the CI/test matrix should include an AMD or Intel GPU at least for smoke runs. [README validation/QA sections](https://github.com/NVIDIA-RTX/NRD/blob/master/README.md), [NRDSettings.h](https://github.com/NVIDIA-RTX/NRD/blob/master/Include/NRDSettings.h), [Releases](https://github.com/NVIDIA-RTX/NRD/releases)

## Gaps

- **Intel-GPU support is unverified.** AMD (Vulkan) is demonstrated (v4.17.3 fix, HDRP, credits); nothing in NRD is vendor-gated, but no direct Intel evidence was found. Add an Intel smoke test to the ticket-08 validation matrix.
- **atlas-rt-specific perf not measured.** Official numbers are RTX 4080 @ 1440p (REBLUR_DIFFUSE_SPECULAR 2.55 ms; memory table ≈148 MB working set / ≈89 MB persistent / ≈59 MB aliasable at the table's first resolution (1080p), scaling ~1.8-2.1x per step to ≈263/158/105 at 1440p and ≈558/335/223 at 4K). The RTX 3070's numbers must be measured on-device in ticket 08.
- **vulkano-side integration details not compiled.** Whether to use the `DescriptorPoolDesc` regular-set path vs raw push descriptors, `ShaderModule::from_bytes` for NRD's SPIR-V blobs, immutable samplers, and the exact taskgraph node/barrier wiring were reasoned from vulkano's known API but not verified in this run. Verify against the pinned vulkano commit in ticket 08.
- **NRD version pinning.** Master is v4.17.4 (header) but the latest tagged release is v4.17.3; the API moved fast across v4.16→v4.17 (settings renames, `IN_BASECOLOR_METALNESS` removal). Pin an exact tag + embedded SPIR-V at integration time and re-check `NRDSettings.h`/`NRD.h` against the pinned tag.
- **License reading is not legal advice.** The EULA summary here (attribution, object-code distribution, clause 4(e), supplement scope) is a faithful summary of LICENSE.txt; whether vendoring NRD into a MIT repo is acceptable for atlas-rt's distribution goals is a project decision to make explicitly in ticket 08.
