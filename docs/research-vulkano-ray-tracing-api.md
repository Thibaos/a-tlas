# Vulkano ray tracing API and limits (git main) — ticket 01

> Research ticket: [.scratch/rendering-core/issues/01-vulkano-ray-tracing-api-and-limits.md](../.scratch/rendering-core/issues/01-vulkano-ray-tracing-api-and-limits.md)
> Verification date: 2026-07-30 (vulkano master HEAD `fb4cfdb56`), source-verified against the vulkano repo at master and at a-tlas's pinned commit `eae054666` (both fetched from GitHub raw at those exact SHAs), plus a-tlas's `Cargo.lock` and `src/`.

## Executive answer

a-tlas's exact vulkano surface (`Cargo.lock` pins git commit `eae054666db41662dbbb94a6ab142e92ed9eda33`, "0.35.0", dated 2026-05-30) is **fully capable of the destination design**: procedural AABB BLASes (`AccelerationStructureGeometries::Aabbs` + `AabbPositions`), RT pipelines with procedural hit groups (intersection + closest-hit + any-hit), SBT, `trace_rays`, refit (`BuildAccelerationStructureMode::Update`, the KHR `vkCmdBuildAccelerationStructuresKHR` mode=UPDATE path), compaction, and taskgraph bindless (AS descriptors at global-set binding 4, `vko_accelerationStructureEXT`). But **current git main (HEAD `fb4cfdb56`, 2026-07-30) has drifted under a-tlas: an unreleased, mid-flight breaking rework** changes exactly the AS-build structs a-tlas uses (`AccelerationStructureGeometries` → `&[AccelerationStructureGeometry]`, scratch `Subbuffer` → `DeviceAddress`, `Update(Arc)` → `Update` + `src_acceleration_structure`) and removes `bind_pipeline_ray_tracing` (unified `bind_pipeline(Pipeline enum)`). **a-tlas's `src/rt/acceleration_structure.rs` and `src/tasks/render.rs` compile against the pin today but will not compile against current main without a port.** Do not `cargo update` the vulkano deps until the port decision is made. Ray queries and opacity micromaps are reference-only: ray queries are shader-side only (vulkano exposes the `ray_query` feature flag, nothing CPU-side); `ext_opacity_micromap` feature flags exist but there is **no micromap API** in vulkano (build flags are commented-out TODOs), and OMM is triangle-only anyway.

## Findings

1. **a-tlas's pin is ~2 months behind main, and the gap is a breaking rework, not patches.** `Cargo.lock` pins all four vulkano crates to git commit `eae054666db41662dbbb94a6ab142e92ed9eda33` ("Fix BuddyAllocator not taking the region's offset into account (#2809)", authored 2026-05-30); master HEAD is `fb4cfdb56998f16b0a1265b813efbec63b93c036` ("Optimize the suballocation lists (#2825)", 2026-07-30). Between them, the unreleased changelog (MSRV 1.88, `Pipeline` enum, `bind_pipeline` unification, `PipelineLayout::from_stages`, AS API rework, glslc-required) landed. [Cargo.lock (a-tlas)](Cargo.lock), [commit eae0546](https://api.github.com/repos/vulkano-rs/vulkano/commits/eae054666db41662dbbb94a6ab142e92ed9eda33), [commit fb4cfdb](https://api.github.com/repos/vulkano-rs/vulkano/commits/fb4cfdb56998f16b0a1265b813efbec63b93c036), [CHANGELOG.md (master)](https://raw.githubusercontent.com/vulkano-rs/vulkano/master/CHANGELOG.md)

2. **What breaks on main, file by file in a-tlas.** `src/rt/acceleration_structure.rs` uses `AccelerationStructureGeometries::Triangles(vec![...])` (→ `geometries: &[AccelerationStructureGeometry<'a>]`), `scratch_data: Some(scratch_buffer)` (→ `scratch_data: DeviceAddress`), `dst_acceleration_structure: Some(acceleration.clone())` (→ `Option<&Arc<...>>`), `BuildAccelerationStructureMode` (Update variant loses its payload; source AS moves to `src_acceleration_structure`), `AccelerationStructureGeometryTrianglesData::new(Format)` with `vertex_data: Some(...)` (→ device addresses + `new()`), and the TLAS `AccelerationStructureGeometryInstancesDataType::Values(...)` (→ `data: DeviceAddress` + `array_of_pointers: bool`). `src/tasks/render.rs` calls `cbf.bind_pipeline_ray_tracing(&self.pipeline)`, which no longer exists on main (taskgraph now has only `bind_pipeline(impl Into<Pipeline>)`, with a `Pipeline::RayTracing` variant). `trace_rays`, `push_constants`, `ShaderBindingTable`, `RayTracingPipelineCreateInfo`, `RayTracingShaderGroupCreateInfo` and the taskgraph bindless calls are **unchanged in shape** and compile as-is. Source-verified at both SHAs. [pinned acceleration_structure.rs](https://raw.githubusercontent.com/vulkano-rs/vulkano/eae054666db41662dbbb94a6ab142e92ed9eda33/vulkano/src/acceleration_structure.rs), [master acceleration_structure.rs](https://raw.githubusercontent.com/vulkano-rs/vulkano/master/vulkano/src/acceleration_structure.rs), [pinned taskgraph pipeline.rs](https://raw.githubusercontent.com/vulkano-rs/vulkano/eae054666db41662dbbb94a6ab142e92ed9eda33/vulkano-taskgraph/src/command_buffer/commands/pipeline.rs), [master taskgraph bind_push.rs](https://raw.githubusercontent.com/vulkano-rs/vulkano/master/vulkano-taskgraph/src/command_buffer/commands/bind_push.rs), [CHANGELOG.md](https://raw.githubusercontent.com/vulkano-rs/vulkano/master/CHANGELOG.md)

3. **Procedural AABB geometry — exact API, both eras.** Pinned: `AccelerationStructureGeometries::Aabbs(vec![AccelerationStructureGeometryAabbsData { flags: GeometryFlags::empty(), data: Some(aabb_subbuffer.into_bytes()), stride: size_of::<AabbPositions>() as u32, ..Default::default() }])`, where the data subbuffer is `Subbuffer<[AabbPositions]>`, `AabbPositions { min: [f32; 3], max: [f32; 3] }` is `#[repr(C)]` `Pod`/`Zeroable`, and the buffer must carry `ACCELERATION_STRUCTURE_BUILD_INPUT_READ_ONLY` (VUID-vkCmdBuildAccelerationStructuresKHR-geometry-03673) plus `SHADER_DEVICE_ADDRESS`. Validated: data device address multiple of 8 (03714), `stride` multiple of 8 (VUID 03545), `primitive_offset` multiple of 8 (03659), bounds vs buffer size. Inactive AABB = `min[0]` is NaN. Main: same structs minus the geometry enum — `AccelerationStructureGeometry::new(AccelerationStructureGeometryData::Aabbs(...))` with `data: buffer.device_address().get()`. [pinned acceleration_structure.rs](https://raw.githubusercontent.com/vulkano-rs/vulkano/eae054666db41662dbbb94a6ab142e92ed9eda33/vulkano/src/acceleration_structure.rs), [master acceleration_structure.rs](https://raw.githubusercontent.com/vulkano-rs/vulkano/master/vulkano/src/acceleration_structure.rs), [pinned command validation](https://raw.githubusercontent.com/vulkano-rs/vulkano/eae054666db41662dbbb94a6ab142e92ed9eda33/vulkano/src/command_buffer/commands/acceleration_structure.rs)

4. **Refit is exposed, under the KHR build command.** `BuildAccelerationStructureMode::Update` maps to `vkCmdBuildAccelerationStructuresKHR` with `mode = VK_BUILD_ACCELERATION_STRUCTURE_MODE_UPDATE_KHR` — that *is* the KHR refit path (`vkCmdUpdateAccelerationStructureKHR` is the deprecated NV-only command; vulkano doesn't wrap NV RT). Constraints documented in vulkano: the update may change scratch, vertex/AABB/instance data buffers, strides and offsets, but must keep the same geometry variant/count, same `primitive_count`, same index values, and may not flip active/inactive items; the dst must have been built with `ALLOW_UPDATE` (in-place update allowed — src == dst). Consequence for a-tlas: value-only changes (camera-driven TLAS rebuilds where instance transforms change) can refit; voxel add/remove changes counts ⇒ rebuild (ticket 02's conclusion holds). [pinned acceleration_structure.rs module docs](https://raw.githubusercontent.com/vulkano-rs/vulkano/eae054666db41662dbbb94a6ab142e92ed9eda33/vulkano/src/acceleration_structure.rs), [master module docs](https://raw.githubusercontent.com/vulkano-rs/vulkano/master/vulkano/src/acceleration_structure.rs), [VkCmdBuildAccelerationStructuresKHR refpage](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdBuildAccelerationStructuresKHR.html)

5. **Limits are queried through `physical_device().properties()`, and builds are validated against them.** a-tlas today: `self.device.physical_device().properties().max_instance_count.unwrap() / 8` then `dbg!` (src/app.rs, verified); ~2M instances on a 2²⁴ driver per the map. Same accessor on main. Fields are `Option<u32>`-style (`unwrap` in a-tlas and upstream examples). vulkano additionally validates at build time: `max_geometry_count` (03793), `max_primitive_count` for AABBs/triangles (03794/03795), `max_instance_count` for TLAS (03801), scratch alignment (03710), plus alignment VUIDs above. [a-tlas src/app.rs](src/app.rs), [pinned command validation](https://raw.githubusercontent.com/vulkano-rs/vulkano/eae054666db41662dbbb94a6ab142e92ed9eda33/vulkano/src/command_buffer/commands/acceleration_structure.rs), [master command validation](https://raw.githubusercontent.com/vulkano-rs/vulkano/master/vulkano/src/command_buffer/commands/acceleration_structure.rs)

6. **Ray queries: shader-side only — nothing to expose CPU-side.** Vulkan has no host-side ray-query API; `VK_KHR_ray_query` is entirely `OpRayQueryProceedKHR` in shaders. vulkano's surface is: `DeviceFeatures::ray_query` (requires `DeviceExtensions::khr_ray_query`) + vulkano-shaders compiling `GL_EXT_ray_query` + the same bindless AS descriptor path. Current main ships only a triangle-based `examples/ray-tracing` (no ray-query example). Confirmed feature flag in `vulkano/autogen-out/features.rs` on master. a-tlas doesn't need it — record as reference/alternative only. [master features.rs](https://raw.githubusercontent.com/vulkano-rs/vulkano/master/vulkano/autogen-out/features.rs), [VK_KHR_ray_query refpage](https://docs.vulkan.org/refpages/latest/refpages/source/VK_KHR_ray_query.html), [Vulkan ray tracing guide](https://docs.vulkan.org/guide/latest/extensions/ray_tracing.html), [examples tree](https://api.github.com/repos/vulkano-rs/vulkano/git/trees/master?recursive=1)

7. **Opacity micromaps: extension flags exist, API does not.** `DeviceExtensions::ext_opacity_micromap` and `DeviceFeatures::{micromap, micromap_capture_replay, micromap_host_commands}` are auto-generated from vk.xml, but `acceleration_structure.rs` (pinned *and* main) has `ALLOW_OPACITY_MICROMAP_UPDATE`, `ALLOW_DISABLE_OPACITY_MICROMAPS`, `ALLOW_OPACITY_MICROMAP_DATA_UPDATE` build flags and `FORCE_OPACITY_MICROMAP_2_STATE`/`DISABLE_OPACITY_MICROMAPS` instance flags commented out with `/* TODO: enable */`; there is no `OpacityMicromap` type anywhere in the tree. Even if it landed, OMM is sub-triangle opacity for triangle geometry and a BLAS can't mix AABBs and triangles — irrelevant to AABB voxels (ticket 02's agreement confirmed). [master acceleration_structure.rs](https://raw.githubusercontent.com/vulkano-rs/vulkano/master/vulkano/src/acceleration_structure.rs), [master features.rs](https://raw.githubusercontent.com/vulkano-rs/vulkano/master/vulkano/autogen-out/features.rs), [VK_EXT_opacity_micromap refpage](https://docs.vulkan.org/refpages/latest/refpages/source/VK_EXT_opacity_micromap.html)

8. **Bindless + vulkano.glsl RT support is the same on both eras and is exactly what a-tlas uses.** Taskgraph global set: bindings 0–3 sampler/sampled image/storage image/storage buffer, binding 4 acceleration structures — added only when the `acceleration_structure` feature is enabled, written via `WriteDescriptorSet::acceleration_structure_array` with UPDATE_AFTER_BIND|PARTIALLY_BOUND flags (requires `descriptor_binding_acceleration_structure_update_after_bind`, which a-tlas enables). `vulkano-shaders/include/vulkano.glsl` mirrors the constants (`VKO_ACCELERATION_STRUCTURE_BINDING 4`) and provides `vko_accelerationStructureEXT(id)` behind `VKO_ACCELERATION_STRUCTURE_ENABLED` plus `VKO_DECLARE_STORAGE_BUFFER`/`VKO_DECLARE_STORAGE_IMAGE` — the header comment says both sides must stay in sync. Push constants carry `StorageImageId`/`AccelerationStructureId`/`StorageBufferId`; ranges come from all pipeline stages via `push_constant_ranges_from_stages`. [taskgraph descriptor_set.rs (main)](https://raw.githubusercontent.com/vulkano-rs/vulkano/master/vulkano-taskgraph/src/descriptor_set.rs), [vulkano.glsl (main)](https://raw.githubusercontent.com/vulkano-rs/vulkano/master/vulkano-shaders/include/vulkano.glsl), [a-tlas src/tasks/render.rs](src/tasks/render.rs)

9. **SBT per-hit data: the built-in helper is handle-only; plan for instance/record data or a hand-built SBT.** `ShaderBindingTable::new` allocates one contiguous buffer (usages TRANSFER_SRC|SHADER_DEVICE_ADDRESS|SHADER_BINDING_TABLE, HOST_SEQUENTIAL_WRITE|PREFER_DEVICE) and writes only group handles (raygen stride = handle size aligned to `shader_group_base_alignment`; miss/hit/callable stride = handle size aligned to `shader_group_handle_alignment`; sizes 16-byte/alignment padded). The buffer is private (`_buffer` field) — there is no API to append per-record user data. Options for the destination: (a) keep a-tlas's instance-custom-index transport for per-hit data (24-bit index, 8-bit mask — `gl_InstanceCustomIndexEXT`); (b) use `instance_shader_binding_table_record_offset_and_flags` (24-bit record offset) to select hit records; (c) build a custom SBT buffer and pass your own `ShaderBindingTableAddresses` (the type is public; `trace_rays` takes addresses, not the helper). [pipeline/ray_tracing.rs (main)](https://raw.githubusercontent.com/vulkano-rs/vulkano/master/vulkano/src/pipeline/ray_tracing.rs)

10. **Known bugs / validation gotchas (vulkano-side).** (a) vulkano#2703 "Acceleration structure alignment issue" (open, 2025-06): AS memory alignment regressions around 0.34.1/0.35.1 — relevant to the pinned era; align AS/scratch to `min_acceleration_structure_scratch_offset_alignment` explicitly when porting (the main example does this). (b) vulkano#2709 "single threaded data race during acceleration structure construction" (open, wontfix/old sync, 2025-07): spurious "OneTimeSubmit command buffer submitted twice" panics during AS builds — a-tlas's `vulkano_taskgraph::execute` + `wait_idle` pattern is the documented workaround. (c) `PREFER_FAST_TRACE`|`PREFER_FAST_BUILD` together → ValidationError (03796). (d) On main, `AccelerationStructureBuildGeometryInfo::ty` must be set explicitly (Generic is rejected, VUID 03654) — the pinned struct derived type from the geometry variant, so this is a port-time trap. (e) Validation-layer gap: VVL does not flag building a TLAS and its referenced BLAS in the same `vkCmdBuildAccelerationStructuresKHR` call (KhronosGroup/Vulkan-ValidationLayers#11078) — keep TLAS builds depending on BLAS builds in separate submissions/flights as a-tlas already does. (f) Fixed on main: a bindless `DescriptorBindingRequirements` validation panic ("When using bindless, the validation checks ... would panic" — changelog). [issue #2703](https://github.com/vulkano-rs/vulkano/issues/2703), [issue #2709](https://github.com/vulkano-rs/vulkano/issues/2709), [VVL #11078](https://github.com/KhronosGroup/Vulkan-ValidationLayers/issues/11078), [CHANGELOG.md](https://raw.githubusercontent.com/vulkano-rs/vulkano/master/CHANGELOG.md)

11. **Deferred host operations exist but are not used for RT pipeline creation.** `vulkano::deferred::DeferredOperation` (create/join/result/wait/max_concurrency, requires `khr_deferred_host_operations`) is present on main, but `RayTracingPipeline::new_unchecked` passes `vk::DeferredOperationKHR::null()` with a `// TODO: RayTracing: deferred_operation` — pipeline creation is always synchronous. a-tlas enables the extension today; that's fine, it just buys nothing until vulkano wires it in. [deferred.rs (main)](https://raw.githubusercontent.com/vulkano-rs/vulkano/master/vulkano/src/deferred.rs), [ray_tracing.rs (main)](https://raw.githubusercontent.com/vulkano-rs/vulkano/master/vulkano/src/pipeline/ray_tracing.rs)

12. **Upstream example on main matches a-tlas's architecture 1:1.** `examples/ray-tracing/` (main) does taskgraph + `vulkano_taskgraph::execute` for AS builds (with `cbf.as_raw().build_acceleration_structure(&info, slice::from_ref(&range))`), `bcx.global_set().add_acceleration_structure(tlas)`, `create_storage_buffer`, `push_constants` with bindless IDs, `bind_pipeline`, `trace_rays`, and keeps the BLAS alive (`_blas` field) because the TLAS references it — same pattern as `src/tasks/render.rs`. It is triangle-based (no AABB example exists anywhere in the repo), so the AABB path must be validated by a-tlas's own port. ## Gaps

- **No upstream AABB/procedural example or test exists** in the vulkano repo (both eras). The exact `AabbPositions` packing, inactive-AABB NaN convention, and the procedural hit path are documented in source and the Khronos spec but not exercised by any vulkano example — a-tlas's AABB port is the first consumer and should be validated with the Vulkan SDK layers + NSight/layer RT validation.
- **Main is mid-rework**: commit-to-commit API churn is ongoing (the unreleased changelog's "Global changes" are still landing). Any main-specific signature in this doc was verified at `fb4cfdb56` (2026-07-30) and may move before the next release; re-verify at port time.
- **SBT record layout with user data**: the built-in `ShaderBindingTable` is handle-only; the exact `shader_group_handle_alignment`/`shader_group_base_alignment` values on the RTX 3070 are device-dependent and were not measured here (owner's `dbg!` run or a one-line probe is needed if a custom SBT is chosen).
- **Perf numbers (build/refit cost, scratch sizes at a-tlas's chunk counts)** are outside this API ticket; ticket 02/06 cover the cost model.
- `DeviceFeatures::ray_query` etc. were confirmed by name from autogen; no compile-test against main was possible in this environment (no git, no cargo build run) — the a-tlas breakage list is from reading both SHAs' sources, not from a compiler.
